# ADR-007: Connection Parity and HTTP Transport Semantics

**Status:** Accepted
**Date:** 2026-10-04

## Context

The Sprint 10 Connection additions exposed gaps in parameter decoding, session lifecycle behavior,
HTTP compression, and adapter conversion. Tests that call a plug directly cannot verify adapter behavior.

## Decision

Keep the value-type Connection and functional Plug model. Add request metadata and header helpers without
changing existing method signatures. `getReqHeaders` and `getRespHeaders` expose individual field values;
the existing singular accessors retain HTTPFields' combined-value behavior. Header updates transform the
first matching field and preserve subsequent fields. Header merges retain Nexus's replacement behavior.

Add `privateData`, `putPrivate`, and `mergePrivate` for framework metadata independent of application assigns.
Existing session data stays in its current assigns keys for compatibility. Session fetching is idempotent,
and a session plug registers one persistence callback per cookie name. A connection has one session data
dictionary; multiple independent session stores on one connection are not supported.

Match [Plug's session option priority](https://github.com/elixir-plug/plug/blob/v1.20.3/lib/plug/conn.ex):
renew, then drop, then ignore. Preserve the existing `clearSession()` logout behavior; use
`clearSession(drop: false)` to clear data without deleting the cookie. Renewal cannot revoke older signed
cookie values because this store has no server-side session identifier.

Decode query and form strings with plus-to-space conversion and last-value precedence. Preserve the
multi-value query accessor. Combined parameters use path values over body values over query values.
This intentionally corrects observable behavior and must be called out in release notes.

Use system zlib through the private CNexusZlib module for gzip and zlib-wrapped deflate on Apple platforms
and Linux. Keep compression in the before-send phase, respect quality values and representation metadata,
and leave streaming bodies unchanged. Parse media preference specificity according to
[RFC 9110 section 12.5.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.1).

Verify transport conversion through the real adapters, including duplicate headers, cookies, query strings,
HEAD/304 metadata, body limits, and streaming failures. Tests using Hummingbird's router client or Vapor
Request/Response objects do not establish live socket, proxy, or production behavior.

## Consequences

- Core code remains independent of a server framework; only compression adds a system library requirement.
- Linux environments must provide zlib development headers, documented and installed in CI.
- Timeout cancellation remains cooperative under structured concurrency; blocking plugs can delay completion.
- This change closes specific Plug compatibility gaps. It does not claim complete API or lifecycle equivalence:
  Nexus retains its response model, string-valued cookie sessions, and adapter-level request body collection.
